# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

A self-hosted home inventory app that replaces Homebox for a single household. One instance tracks one home: locations, items nested inside them, tags, and photos, with no authentication in v1.

## Commands

### Backend (Rust)

```bash
just site-placeholder   # once: stub site/build/index.html so cargo build has something to embed
cargo run                # dev server on :7008
cargo test               # run all tests
just test                # tests, re-run on file changes (watchexec)
just cover                # lcov coverage report (cargo llvm-cov)
just import <path>        # cargo run -- import <path>, upserts a Homebox backup
```

### Frontend (`cd site` first)

```bash
yarn dev          # dev server, proxies /graphql, /graphiql, /attachments, /api to :7008
yarn build        # tsc + Vite build → site/build/
yarn test         # vitest
yarn lint         # ESLint
```

Also run `yarn install` once at the **repo root** (not just in `site/`); it activates the husky pre-commit hook via the root `prepare` script.

### Database

```bash
diesel migration generate <description>   # create new migration
diesel migration run                      # apply migrations (embedded copy also runs on every boot)
diesel migration revert                   # revert last migration
diesel print-schema > src/schema.rs       # regenerate schema after migration
```

## Architecture

Single Rust crate at the repo root with an embedded, Vite-built React frontend. Diesel migrations are embedded in the binary and run automatically on startup.

### Backend (`/src/`)

- `main.rs`: clap CLI: `serve` (default), `import`, `healthcheck`; jemalloc on musl
- `lib.rs`: `init_tracing`, module re-exports
- `config.rs`: `Config` from `PORT`/`LISTEN_ADDRESS`/`DATABASE_URL`/`DATA_DIR`
- `net.rs`: dual-stack bind
- `db.rs`: r2d2 pool, PRAGMA customizer, embedded migrations, `TestDb` for tests, seeded type ids
- `schema.rs`: auto-generated by Diesel, do not edit manually
- `asset_id.rs`: `AssetId`, Homebox-style asset numbers displayed as `000-007`
- `money.rs`: `Cents`, money as integer minor units
- `kinds.rs`: closed string enums (`AttachmentKind`, `FieldKind`) stored as lowercase TEXT
- `models/`: one file per table, Diesel `Queryable`/`Selectable` structs
- `svc/`: business logic, one file per aggregate (`entity.rs`, `tag.rs`, `attachment.rs`, `settings.rs`, `stats.rs`, `fixtures.rs`)
- `graphql/`: juniper: `context.rs` (`GraphQLContext`, `Actor`, `Role`), `schema.rs` (`RootNode`), `query.rs`, `objects/` (one file per GraphQL type)
- `import/`: Homebox backup importer: `source.rs` (zip or directory), `tables.rs` (row structs), `run.rs` (upsert), `report.rs`
- `api/`: axum handlers: `graphql.rs` (`/graphql` is POST only; there is no auth in v1, so a GET-triggered mutation would be a LAN CSRF path; `/graphiql` in debug builds)
- `routes.rs`: router, compression, embedded SPA, `/assets` immutable cache
- `healthcheck.rs`: liveness probe used by the Docker `HEALTHCHECK`

### Frontend (`/site/src/`)

- `App.tsx` / `main.tsx`: Apollo Client setup, router, lazy-loaded pages
- `theme/`: `tokens.css`, `ThemeProvider`, `useTheme`
- `hooks/`: one hook per GraphQL operation (Apollo `useQuery`/`useMutation`), `queries.ts`
- `components/`: reusable UI (`AppHeader`, `Sidebar`, `StatCard`)
- `page/`: page-level components (`PageTemplate`, `HomePage`)
- `types/`: hand-written TypeScript interfaces mirroring the GraphQL schema
- `utils/`: small pure helpers (`currency.ts`)

## Key Conventions

**GraphQL naming**: Rust fields are `snake_case`; Juniper auto-converts to `camelCase`. Boolean fields do NOT use an `is` prefix, except `isLocation`, which matches Homebox's own vocabulary and stays.

**Frontend GraphQL**: every operation lives in exactly one hook under `site/src/hooks/`. Components never import Apollo directly.

**Error handling**: backend handlers return `anyhow::Result`/`AppError`; GraphQL resolvers use `graphql_translate_anyhow`. Frontend errors surface via `toast.error()` (see `useErrorToast`), never inline in a query result.

**Package manager**: always `yarn` in `site/`, never `npm`.

**Semantic theme tokens only**: components use only these Tailwind classes derived from `theme/tokens.css` variables:
`bg-bg`, `bg-surface`, `bg-surface-raised`, `border-border`, `text-text`, `text-muted`, `bg-accent`, `text-accent`, `text-accent-text`, `text-danger`, `text-success`.
Never a raw palette class like `bg-zinc-900`. A theme is exactly one block of `--t-*` variables in `theme/tokens.css` under a `[data-theme]` selector; adding a raw palette class silently breaks the second theme.

**Button cursors**: Tailwind v4's Preflight resets buttons to `cursor: default`. `site/src/index.css` restores `cursor: pointer` for non-disabled buttons and `[role="button"]` in one base rule; don't add `cursor-pointer` per button.

**Mutations must gate on `ctx.require_write()`**: there are no mutation resolvers yet (the schema uses `EmptyMutation`). When phase 4 adds them, every mutation resolver calls `ctx.require_write()?` first; `Actor::Anonymous` can write in v1 and auth later fills the actor.

**`site/build/index.html` must exist before `cargo build`**: `routes.rs` embeds `site/build/` via `rust-embed` at compile time. Run `just site-placeholder` (stub) or `just build-site` (real bundle) first; both `just test` and `just cover` do this automatically.

**The `immutable_cache` layer position in `routes.rs` is load-bearing**: it must be added after the `/assets` route and before the SPA fallback, or the SPA shell (and a missing-asset 404) would be cached immutably too. Pinned by `tests/spa_routes.rs`.

**Money is integer cents.** Amounts are `*_cents: Int` over GraphQL and formatted client-side with `formatCents` (`utils/currency.ts`); never store or transmit a float dollar amount. Backend values use `Cents` (`money.rs`); asset numbers use `AssetId` (`asset_id.rs`), which displays as `000-007` and is `None`/empty at 0.

**`homebox/` and `homebox-backup/` are local reference material**, excluded via `.git/info/exclude`. Never `git add` them.

**The importer keeps Homebox's UUIDs** as primary keys and upserts by them, so re-running an import is safe. Homebox's two built-in entity types are matched by name (`global.location`, `global.item`) and mapped onto the seeded location/item type ids instead of being inserted again.

**Enum columns are lowercase TEXT behind `kinds.rs`.** `AttachmentKind` and `FieldKind` round-trip through `FromStr`/`Display`; never match on the raw column string elsewhere.

**Every `svc` read returns `Selectable` models via `as_select()`.** Diesel queries select a model's own columns this way rather than listing them by hand, so adding a column to a model cannot silently desync a query.
