# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

A self-hosted home inventory app that replaces Homebox for a single household. One instance tracks one home: locations, items nested inside them, tags, and photos, with no authentication in v1.

## Commands

### Backend (Rust)

```bash
just site-placeholder   # once: stub site/build/index.html so cargo build has something to embed
cargo run                # dev server on :7008
cargo test               # run all tests
just test                # tests, re-run on file changes (watchexec)
just cover                # lcov coverage report (cargo llvm-cov)
just import <path>        # cargo run -- import <path>, upserts a Homebox backup
```

### Frontend (`cd site` first)

```bash
yarn dev          # dev server, proxies /graphql, /graphiql, /attachments, /api to :7008
yarn build        # tsc + Vite build → site/build/
yarn test         # vitest
yarn lint         # ESLint
```

Also run `yarn install` once at the **repo root** (not just in `site/`); it activates the husky pre-commit hook via the root `prepare` script.

### Database

```bash
diesel migration generate <description>   # create new migration
diesel migration run                      # apply migrations (embedded copy also runs on every boot)
diesel migration revert                   # revert last migration
diesel print-schema > src/schema.rs       # regenerate schema after migration
```

## Architecture

Single Rust crate at the repo root with an embedded, Vite-built React frontend. Diesel migrations are embedded in the binary and run automatically on startup.

### Backend (`/src/`)

- `main.rs`: clap CLI: `serve` (default), `import`, `healthcheck`; jemalloc on musl
- `lib.rs`: `init_tracing`, module re-exports
- `config.rs`: `Config` from `PORT`/`LISTEN_ADDRESS`/`DATABASE_URL`/`DATA_DIR`; `net.rs`: dual-stack bind
- `ai/`: model calls: `client.rs` (`AiClient` trait, `ChatRequest`, `AiError`, whose messages never carry the key), `openai.rs` (`OpenAiClient`: `POST {base_url}/chat/completions`, retries 429/5xx after 1 s and 4 s, one `json_schema` to `json_object` fallback, error bodies masked and cut to 500 chars, the cap sent as `max_completion_tokens`), `fake.rs` (`FakeAiClient`, a scripted queue for tests), `prompts.rs` (system prompts and the §4.4/§4.5 schemas), `env.rs` (`OPENAI_*` overrides); `routes::app` uses `OpenAiClient`, tests use `app_with_ai`
- `db.rs`: r2d2 pool, PRAGMA customizer, embedded migrations, `TestDb` for tests, seeded type ids
- `schema.rs`: auto-generated by Diesel, do not edit manually
- `asset_id.rs`: `AssetId`, Homebox-style asset numbers displayed as `000-007`
- `money.rs`: `Cents`, money as integer minor units
- `kinds.rs`: closed string enums (`AttachmentKind`, `FieldKind`) stored as lowercase TEXT
- `models/`: one file per table, Diesel `Queryable`/`Selectable` structs
- `svc/`: business logic, one file per aggregate (`entity.rs`, `entity_type.rs`, `entity_field.rs`, `tag.rs`, `attachment.rs`, `settings.rs`, `ai_settings.rs` (`ai.*` rows under `OPENAI_*` env overrides; the key is write-only), `stats.rs`, `thumbnail.rs` sizes/MIME gate/decode limits, `thumbnail_service.rs` generate-or-cache by `Blob`, `blob.rs` (sha256 plus MIME, what the thumbnailer sees), `sniff.rs` magic-byte format detection, `upload.rs` temp file, dedupe, primary rule); `fixtures.rs` is test support (the shared sample inventory)
- `graphql/`: juniper: `context.rs` (`GraphQLContext`, `Actor`, `Role`), `schema.rs` (`RootNode`), `query.rs`, `objects/` (one file per GraphQL type)
- `import/`: Homebox backup importer: `source.rs` (zip or directory), `tables.rs` (row structs), `run.rs` (upsert), `report.rs`
- `api/`: axum handlers: `graphql.rs` (`/graphql` is POST only; there is no auth in v1, so a GET-triggered mutation would be a LAN CSRF path; `/graphiql` in debug builds), `attachments.rs` (`/attachments/{id}` and its `/thumb/{size}`), `upload.rs` (`POST /api/upload/{entityId}` multipart, 25 MiB limit on that route only, JSON errors), `actor.rs` (middleware attaching the request's `Actor`; handlers read `Extension<Actor>`)
- `routes.rs`: router, `attach_actor` outermost, compression (not attachments or uploads), embedded SPA, `/assets` immutable cache; `app_with_actor` is the test seam for a read-only actor
- `healthcheck.rs`: liveness probe used by the Docker `HEALTHCHECK`

### Frontend (`/site/src/`)

- `App.tsx` / `main.tsx`: Apollo Client setup, router, lazy-loaded pages
- `theme/`: `tokens.css`, `ThemeProvider`, `useTheme`
- `hooks/`: one hook per GraphQL operation (`useSummary`, `useLocations`, `useEntity`, `useSearch`, `useRootItems`), `queries.ts`; `useUploadPhoto` posts to `/api/upload/{id}` with `fetch`, one file at a time, and reports per-file status (no byte progress)
- `components/`: reusable UI (`AppHeader`, `Sidebar`, `LocationTree`, `Breadcrumbs`, `LocationCards`, `EntityList`, `Thumb`, `SearchBox`, `StatCard`, `DetailsGrid`, `TagChips`, `PhotoUploader` (Add photos button plus drop zone), `PhotoGallery` (300 thumbs, Primary badge, Make primary, Delete), `Lightbox` (1200 viewer dialog))
- `page/`: page-level components (`PageTemplate`, `HomePage`, `LocationPage`, `ItemPage`, `SearchPage`, `NotFound`)
- `types/`: hand-written TypeScript interfaces mirroring the GraphQL schema
- `utils/`: small pure helpers (`currency.ts`, `date.ts`, `locationTree.ts` builds the sidebar tree from flat `locations`, `thumbUrl.ts`, `uploadErrors.ts` maps upload statuses to messages, `photos.ts`, `color.ts` hex guard for tag swatches, in step with `svc/tag.rs::optional_color`)

## Key Conventions

**GraphQL naming**: Rust fields are `snake_case`; Juniper auto-converts to `camelCase`. Boolean fields do NOT use an `is` prefix, except `isLocation`, which matches Homebox's own vocabulary and stays.

**Frontend GraphQL**: every operation lives in exactly one hook under `site/src/hooks/`. Components never import Apollo directly.

**Error handling**: backend handlers return `anyhow::Result`/`AppError`; GraphQL resolvers use `graphql_translate_anyhow`. Frontend errors surface via `toast.error()` (see `useErrorToast`), never inline in a query result.

**Package manager**: always `yarn` in `site/`, never `npm`.

**Semantic theme tokens only**: components use only these Tailwind classes derived from `theme/tokens.css` variables:
`bg-bg`, `bg-surface`, `bg-surface-raised`, `border-border`, `text-text`, `text-muted`, `bg-accent`, `text-accent`, `text-accent-text`, `text-danger`, `text-success`.
Never a raw palette class like `bg-zinc-900`. A theme is exactly one block of `--t-*` variables in `theme/tokens.css` under a `[data-theme]` selector; adding a raw palette class silently breaks the second theme.

**Button cursors**: Tailwind v4's Preflight resets buttons to `cursor: default`. `site/src/index.css` restores `cursor: pointer` for non-disabled buttons and `[role="button"]` in one base rule; don't add `cursor-pointer` per button.

**Mutations gate on `ctx.require_write()`**: all thirteen `Mutation` resolvers (`graphql/mutation.rs`) call it first, before any input is parsed; a `Role::ReadOnly` actor gets `Forbidden` and no row changes. `Actor::Anonymous` can write in v1. **The actor seam:** `api/actor.rs::attach_actor` puts the `Actor` into every request's extensions, and `/graphql` and the upload handler read `Extension<Actor>`; never build an `Actor` in a handler, since auth will change only that middleware.

**Frontend refetch and eviction**: every mutation hook builds on `useRefetchingMutation` (`hooks/useRefetchingMutation.ts`) with a list of `GetLocations`, `GetSummary`, `GetRootItems`, `GetEntityTypes`, `GetTags` (plus `GetEntity`): after any write, active queries in the list are refetched and inactive ones have their root field evicted (every cached `search` too); create, update and delete all evict the affected entity's parent(s) (`Entity:<id>`, both parents on a move) before `cache.gc()`. A write outside Apollo (the `fetch` photo upload) calls the exported `refetchAfterWrite(client, refetch, ids)` from the same file so both paths share one policy.

**`EntityForm` is shared** (`components/EntityForm.tsx`) between create and edit, keyed by the entity's id in edit mode so a different entity remounts it instead of reusing stale state; parent and tags go through `LocationPicker`/`TagPicker`.

**No `window.confirm`/`alert`**: every delete goes through `<ConfirmDialog>` (`role="dialog"`, labelled, focus on Cancel at open, Escape cancels). **`updateEntity` replaces every field**: the frontend always sends the full `EntityInput`; an omitted optional scalar resets to its default, and an omitted `tagIds` leaves tags alone while `[]` clears them.

**`site/build/index.html` must exist before `cargo build`**: `routes.rs` embeds `site/build/` via `rust-embed` at compile time. Run `just site-placeholder` (stub) or `just build-site` (real bundle) first; both `just test` and `just cover` do this automatically.

**The `immutable_cache` layer position in `routes.rs` is load-bearing**: it must be added after the `/assets` route and before the SPA fallback, or the SPA shell (and a missing-asset 404) would be cached immutably too. Pinned by `tests/spa_routes.rs`.

**Money is integer cents.** Amounts are `*_cents: Int` over GraphQL and formatted client-side with `formatCents` (`utils/currency.ts`); never store or transmit a float dollar amount. Backend values use `Cents` (`money.rs`); asset numbers use `AssetId` (`asset_id.rs`), which displays as `000-007` and is `None`/empty at 0.

**`homebox/` and `homebox-backup/` are local reference material**, excluded via `.git/info/exclude`. Never `git add` them.

**The importer keeps Homebox's UUIDs** as primary keys and upserts by them, so re-running an import is safe. Homebox's two built-in entity types are matched by name (`global.location`, `global.item`) and mapped onto the seeded location/item type ids instead of being inserted again. **Homebox `path` is ignored:** the importer finds each attachment's blob in the backup by its attachment id and stores it by content hash; Homebox's opaque `path` column plays no part.

**Enum columns are lowercase TEXT behind `kinds.rs`.** `AttachmentKind` and `FieldKind` round-trip through `FromStr`/`Display`; never match on the raw column string elsewhere.

**`svc` reads that return whole rows use `Selectable` models via `as_select()`; scalar reads (`settings::currency`, the `stats` aggregates) select columns directly.** Selecting a model's own columns this way rather than listing them by hand means adding a column to a model cannot silently desync a query. SQLite `LIKE`/`lower()` fold case for ASCII only; non-ASCII names sort and match case-sensitively (known limitation).

**Attachment URLs carry `?v=<sha256 prefix>`** so they can be cached forever by the browser and still change after a re-import; `is_thumbnailable` (`svc/thumbnail.rs`) is the single MIME gate other code should call rather than re-checking MIME types. Thumbnails are keyed by `(sha256, size)`, not by attachment, so rows sharing bytes share them; `ThumbnailService` takes a `Blob` and never an `Attachment`, and remembers an original that failed to decode (by sha256, checked after stored thumbnails, for the process lifetime) so it answers 404 without decoding it again; 500 bodies never carry a filesystem path (log it instead).

**Uploads trust bytes, not names.** `svc/sniff.rs` decides the format from magic bytes (JPEG, PNG, GIF, WebP, else 415); the client's content type is ignored and its filename only becomes the title via `clean_title`. `store` then reads the header as the sniffed format within `thumbnail::decode_limits()` (8192px edge, 256 MiB decode) and generates the 300px thumbnail in the same blocking step (stored with the row), else 422 with no row or file, so every stored photo can be thumbnailed. The handler refuses a read-only actor (403) before reading the body, but the `RequestBodyLimitLayer` (25 MiB file plus 64 KiB of form) wraps the route, so an over-limit `Content-Length` gets 413 first; browsers usually see that as a reset, so `useUploadPhoto` refuses a file over `MAX_UPLOAD_BYTES` itself. The `file` field alone is capped at 25 MiB while streaming. Every error is JSON `{ "error" }`.

**Originals are shared by sha256, guarded by the placing claim.** An upload holds a `PlacingOriginal` claim (`svc/attachment.rs`) from before it checks for or renames its file until its row commits; `remove_original` skips a claimed file and counts sharers under the same lock, then deletes the sha's thumbnail rows before the file. A re-import that changes an attachment's bytes calls it for the old sha after its transaction. The claim is in-process: `home-tracker import` into a data dir a live server is using can still race a delete there (known limitation; re-importing restores the file). Deleting the primary photo promotes the earliest remaining thumbnailable one.

**The location tree is built client-side.** `useLocations` fetches the flat `locations` query and `utils/locationTree.ts` assembles it into a `LocationNode` tree; there is no server-side tree query.
